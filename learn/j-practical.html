Appendix J · step 6

From Hugging Face to your GPU

The reusable workflow: download a model, convert and quantize it, check it, run it well, including a model bigger than the GPU, and publish it. Measured on Qwen3.5-2B (the whole conversion in under 4 minutes) and on the unpruned 35 B at Q4_K_M, a 20.5 GiB file on a 16 GB card.

Try it: build the command for your setup

GPU memory = weights on the GPU (measured) + KV cache (20 KiB per token in f16, 10.6 KiB in q8_0) + about 0.4 GiB of buffers; about 14.6 GiB were free on this card with the desktop running (it varies with what else uses the GPU: the measured N = 12 run, at 8k context, was right at the limit). Speeds are the measured ones (step 4 and the offload sweep), interpolated between the measured N. The N slider only matters for the 35 B Q4_K_M, the one file here that does not fit.

What to remember

Download what you need. hf download REPO FILE --local-dir DIR for one file of a GGUF repo; hf models info and the repo page show what is there. A token (hf auth login) is needed for gated models and uploads.

Convert, quantize, then check. scripts/make_gguf.sh REPO TYPES… does download → BF16 GGUF → imatrix → quantize → perplexity of every file. Small models pay more for each bit: the 2 B lost 3.7% at Q4_K_M where the 19 B MoE lost nothing measurable. Very low-bit types need imatrix data for every tensor, which an unused MTP head never gets.

Fit first, then offload. If a good quantization fits in VRAM, use it: the 35 B at 12 GiB ran at 173 tokens per second. A MoE that does not fit can keep its experts in system RAM with --n-cpu-moe N: 78 tokens per second with 12 layers' experts in RAM, still 33 with all of them there and under 3 GB of VRAM used.
