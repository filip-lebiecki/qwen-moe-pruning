Chapter 3

Experts and Mixture of Experts

Instead of one big feed-forward block, each layer has 256 small ones, the experts, and every token uses only 8 of them. That is how a model can store 35 B parameters but run only about 3 B per token.

Try it: experts per token

Active parameters = everything that is not a routed expert (attention, DeltaNet, shared experts, embeddings, lm_head: 2.43 B) + k experts x 3.15 M x 40 layers. Qwen trained the model with k = 8; changing k on a trained model hurts quality, the slider only shows the arithmetic. Generation speed follows active parameters, memory follows total parameters.

What to remember

An expert is a tiny feed-forward network: gate_proj and up_proj (2048 → 512), a SiLU gate, and down_proj (512 → 2048). That is 3 x 2048 x 512 = 3.1 M parameters. Each layer has 256 of them plus one shared expert that every token always uses.

In the checkpoint the 256 experts are stacked into one tensor, mlp.experts.gate_up_proj with shape [256, 1024, 2048], so expert 17 is just slice [17]. Removing an expert means removing a slice, which is why expert pruning is so mechanically simple.

The catch of MoE: you do not know which experts the next token will need, so all of them must be in memory. Pruning attacks exactly that.
