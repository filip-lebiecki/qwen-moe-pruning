Chapter 7

Calibration data

Every importance score comes from the text we run through the model. Experts that never fire on the calibration text look useless and get deleted, even if they are essential for something else.

Try it: build your own calibration mix

Simulated layer: each expert has a made-up affinity for the four kinds of text, with about a third of them specialists. Experts are kept by how much they are used on the calibration mix you set. The bars show how much of each domain's routing still lands on a kept expert, which is a good early warning for where quality will drop.

What to remember

Our calibration set (02_calib_data.py) is 4 x 131k tokens: educational web text, chat conversations, math reasoning and code reasoning, with chat and reasoning rendered through the model's chat template so the router sees the real special tokens.

The statistics found many specialists, experts that get more than 60% of their tokens from one source. At K = 128 the prune still dropped 170 web specialists, and web and wikitext were the domains that lost the most quality. Reasoning text (math and code traces were half of the calibration set) survived best.

For a model that only has to be good at code, calibrate on code only. It will keep the code experts and lose more of everything else. Calibrating is choosing what to keep.

Measured in run 3: pruned to 48 experts (8.9 B), the code-calibrated model lost only 15% on held-out code (perplexity 2.80 → 3.23) where the general-calibrated one lost 69% (→ 4.73). It passed 12 of 15 graded coding answers, against 10 of 15 for the 19 B general model. On general text it got much worse, and when asked for the capital of Australia it answered "A", explaining capital letters and Unicode.
