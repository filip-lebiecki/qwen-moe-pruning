Benchmarking: does the pruned model still do the job?

Perplexity says how well a model predicts text. A benchmark says whether it can do a task: solve the math problem, write code that passes the tests, pick the right answer. Here are three benchmarks, how each is graded, how to read their uncertainty, and the results for the original model and both pruned models.

Try it: is a difference real or noise?

The bars are 95% Wilson confidence intervals: if you re-ran the benchmark on a fresh set of questions of the same kind, the true score would fall inside the bar 95% of the time. Start at 15 questions with 12 vs 10 correct (80% vs 67%), the graded test from run 3: the intervals overlap almost completely. Slide to 300 questions and the same percentages become clearly different.

What to remember

Grade automatically, and check the grader first. 08_bench.py extracts the final number (GSM8K), runs the code against hidden tests (HumanEval), or reads the most likely letter (MMLU). Before trusting it, every grader was run on the reference answers: 250/250, 164/164 and 300/300 must pass, and wrong answers must fail.

Graders fail too. The first MMLU run scored 13.7%, below the 25% of random guessing. The model was fine; the parser did not recognise "The correct option is **B**". The fix was to stop parsing free text and score the probability of each letter instead, which also stops measuring how chatty a model is.

Report uncertainty. 15 graded answers could not separate the two pruned models; 164–300 questions per task can. Same decoding settings (greedy, thinking off) for every model, so differences come from the models.
