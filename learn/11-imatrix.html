Chapter 11

The importance matrix (imatrix)

Not all rounding errors hurt equally. A weight that multiplies a usually-large input matters more than one that multiplies a usually-tiny input. The imatrix measures input sizes on calibration text, and the quantizer spends its precision where it counts.

Try it: when does the imatrix help most?

Both methods use the same bits and the same number of levels; they only choose the block's scale and minimum differently. Output error is measured on 2000 simulated calibration inputs. When all inputs are equally large the two methods agree; the more uneven the inputs, the more the imatrix helps. Real hidden states are very uneven (a few channels carry huge values), which is why the imatrix matters so much for 4-bit and lower.

What to remember

Each output of a matrix is y = Σ_j w_j · x_j. Rounding w_j to q_j changes the output by Σ_j (w_j − q_j) · x_j, so on average the output error is Σ_j E[x_j²] · (w_j − q_j)². Columns whose inputs are usually large dominate.

llama-imatrix runs calibration text through the full-precision model and, for every weight matrix (every expert separately), stores imp_j = mean(x_j²) per input column. llama-quantize then picks each block's scale to minimise the weighted error Σ imp_j · (w_j − q_j)². It is called a matrix because the full version would be XᵀX; llama.cpp keeps only its diagonal.

Same idea as REAP, one level down. REAP uses calibration data to decide which experts survive, and the imatrix uses it to decide which weight columns get the precision.
