Specialist pruning: the same 9 B, calibrated on code

With 48 of 256 experts per layer, a general calibration broke the model. The same budget calibrated on code only gave a model that passes Python unit tests. Same pruning code, same K; only the calibration text changed. Every grid and number here comes from the two statistics files of this project.

Try it: compare the two selections in any layer

Real REAP rankings from stats/calib.pt (general calibration) and stats/code.pt (code calibration). "Routing kept" = share of that kind of text's top-8 picks that land on a kept expert in this layer.

What to remember

Pruning keeps what the calibration text uses. A general mix spreads 48 experts thinly over web text, chat, math and code, and none of them is covered well enough. A code-only mix spends all 48 on code: code tokens keep 39% of their routing instead of 27%, and held-out code perplexity rises only 15% instead of 69%.

The two selections still share about two thirds of their experts (68% at K = 48), because many experts are useful for any text: grammar, formatting, numbers. The difference is in the remaining third, and it is largest in the middle layers (layer 14: only 37.5% shared).

"Routing mass kept" is a proxy, not the whole story. On general text, both selections keep about 28% of the routing, yet the code model's general perplexity is much worse (16.4 against 11.7). REAP keeps experts by contribution, and the code selection dropped the experts that contribute most to general text, even where it kept similarly busy ones.
