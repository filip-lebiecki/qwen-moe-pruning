Training: how distillation changes the routers

Every page before this one only ran the model. Here its weights change. One training step is a forward pass, a loss, a backward pass and an optimizer step; this page animates each of them as they happen in 10_distill.py, on a GPU too small to hold the model, and ends with this run's real loss curve.

Try it: gradient descent playground

One weight w and a bumpy loss curve. Each step moves w against the gradient, scaled by the learning rate; "batch noise" perturbs the gradient the way a random batch of text does. Try a tiny learning rate (slow), the default (converges), and the maximum (overshoots and diverges). Real training does this for 10.5 million router weights at once.

What to remember

Training loop: forward pass → loss → backward pass (gradients by the chain rule, from the loss back to the first layer) → optimizer step (each weight moves against its gradient, scaled by the learning rate). Repeat with a new batch. Watch a held-out validation loss, not the noisy training loss.

Training on a GPU that is too small: keep each layer's input in RAM during the forward pass, then reload the layers in reverse and recompute each one's forward pass with gradients on. Only one layer is ever on the GPU. The cost is reading the model twice per step.

Trust, but verify: a finite-difference check (nudge a weight, re-run, compare the change in loss with the gradient's prediction) caught nothing wrong in the streamed backward pass, but its first version raised a false alarm, because the nudge has to be large enough to survive bf16 rounding and small enough not to change which experts get picked.
