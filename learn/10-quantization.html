Chapter 10

Quantization, GGUF, Q4_K_M and IQ4_XS

Quantization stores each weight in fewer bits. Weights are grouped into small blocks; each block gets a scale, and every weight is rounded to one of 16 levels. The rounding error is the price; here you can watch it.

Try it: bits versus error

Error = root-mean-square difference between the original and the rounded weights of this block, relative to the weights' own spread. Each extra bit halves the error. Size assumes 19 B parameters plus 0.5 bits per weight of scales.

What to remember

BF16 is 16 bits per weight. A 4-bit format uses about 4.5 bits including the per-block scales, so the 19 B pruned model goes from 36 GiB to 9.5–11 GB, and generation gets faster too, because inference mostly waits for weights to be read from memory.

GGUF is llama.cpp's single-file format (weights, tokenizer, architecture settings). Q4_K_M is a "k-quant": blocks of 32 inside super-blocks of 256 whose block scales are themselves stored in 6 bits; "M" mixes in 6-bit for a few sensitive tensors. About 4.8 bits per weight. IQ4_XS is an "i-quant": 4.25 bits per weight with non-uniform levels that are denser near zero, where most weights are. It needs the importance matrix (chapter 11) to be at its best.
