Chapter 14

Number formats: FP32, FP16, BF16 and integers

Every weight and activation is a floating-point number: a sign, an exponent (which power of two) and a mantissa (the digits). How many bits each part gets decides the range and the precision. This page decodes a real weight of this model bit by bit, shows which numbers the model actually needs, and why the order of additions changes the answer.

Try it: store a number in each format

Red = sign, amber = exponent, blue = mantissa. Rounding is round-to-nearest-even, as the hardware does. Values beyond a format's range become infinity; values below it lose digits (subnormal) and then become 0.

What to remember

Value = ±1.mantissa x 2^exponent. Exponent bits buy range, mantissa bits buy precision. FP32 has 8 + 23, FP16 5 + 10, BF16 8 + 7.

BF16 is FP32 with the last 16 bits cut off: the same range (up to 3.4 x 10³⁸, down to 10⁻³⁸) with about two significant digits. FP16 has more digits but stops at 65,504 and at 6 x 10⁻⁵ (then subnormals down to 6 x 10⁻⁸). In this model 0.43% of one expert's weights sit below FP16's normal range; the hidden state never exceeds 41.

Each operation rounds. Near 5, BF16 can only store steps of 1/32, so (a + b) + c and a + (b + c) can differ: 5.625 − 0.387 − 0.387 gives 4.875 one way and 4.844 the other (exact: 4.852). GPU threads that add in a varying order give varying results; that was bug 4.
